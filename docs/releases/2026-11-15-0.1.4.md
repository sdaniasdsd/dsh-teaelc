# @commonworks/dsh-circuit 0.1.4

**修掉「侧边栏没有入口」的真正原因。** 0.1.3 让页面本身完全可用，但插件在 DSH
界面里始终不出现 —— 这一版解决了它。

## 根因

在隔离的 DSH 实例（0.2.1-rc.5，与桌面端同版本）里实测，宿主抛出：

```
client-modules: duplicate factory registration for "dsh-circuit"
              (bundle executed twice without invalidate?)
web boot: 1 entry did not activate
```

`client-modules` 的 `register()` 用 `registration.id` 作为 factories 表的键，而
模块图里那一行的 `id` 是**包名** `@commonworks/dsh-circuit`。`client.js` 里写的是
裸名 `dsh-circuit`，于是同一个 bundle 占两个键，注册阶段直接抛错，整个客户端条目
装载失败 —— 侧边栏自然没有入口。

**这个故障最阴的地方**：Host 路由 `/dsh-circuit/` 依然返回 200，页面单独打开也
完全正常。只检查路由的测试会判成"装好了"，所以拖到 0.1.3 之后才被发现。

## 修复

- `client/client.js` 的 `id` 改为全限定包名，与 `package.json` 的 `name`、
  `cordis.patch.yml` 的 `name` 逐字一致
- 新增回归哨兵（`test/manifest.test.mjs`）：bundle 注册 id 必须等于包名
- `client-harness.mjs` 改为用全限定名取 registration
- 新增 `iso-verify.mjs`：在隔离 DSH 实例里验证 模块图含本插件 / 侧边栏出现 /
  点击能打开主区 iframe

## 验证

这个 tgz **逐个验过**：

1. 全新 `npm install` 该 tgz，`client/client.js` 里的 id 确认为全限定名
2. 用它装进一个隔离的 DSH profile，宿主启动**不崩溃**
3. 模块图 71 条，含 `@commonworks/dsh-circuit`
4. 侧边栏出现「电路小实验」，点击后在主区打开模拟器
5. 控制台**无任何错误**（0.1.3 的那个 `did not activate` 已消失）

源码测试：`npm test` 22 条、`npm run test:browser` 59 条、
`CIRCUIT_ISO=1 npm run test:browser` 追加 5 条隔离宿主断言，全绿。

## 升级须知

**必须重启 DSH。** 客户端 bundle 在页面加载时注册，不重启宿主不会重新拉取。
如果你正在用 0.1.3，先移除再装，或直接 `dsh plugin --profile <你的profile> add`
覆盖安装后重启。
