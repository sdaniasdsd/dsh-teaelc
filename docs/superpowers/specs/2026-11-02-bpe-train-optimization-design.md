# BPE 常规训练提速设计

**状态：已获用户批准（2026-11-02）**  
**范围：第一阶段——常规 BPE 训练优化与官方测试。** 特殊训练规则/编号映射实验留作后续独立分支，不纳入本阶段实现。

## 目标与依据

让当前 `train_bpe` 在官方 `corpus.en`、`vocab_size=500`、`special_tokens=["<|endoftext|>"]` 配置下通过官方 `<1.5s` 速度测试，同时保持官方 merge 序列、vocab 与 special-token 测试完全一致。此前官方速度测试实测约 5.61 秒，另两项正确性测试通过。

当前实现已把相同的 GPT-2 预分词片段按频次压缩；主要开销是每个 merge 轮次重新扫描所有不同片段统计 pair 频次，并重新构建全部片段序列。优化不改变公开调用形式 `train_bpe(text, vocab_size, special_tokens=None)`、词表定义、预分词、special-token 切分或编码行为，也不增加依赖。

## 方案

保留按预分词片段频次加权的表示。训练开始时建立全局 pair 频次和 pair 到受影响片段的索引；维护一个带惰性过期项校验的最大优先队列。每轮选择真实当前频次最高的 pair 后，只更新包含该 pair 的不同片段：在片段内按现有从左到右、非重叠规则执行合并，并基于该片段合并前后的局部 pair 变化、乘以片段频次，更新全局频次和索引。

必须严格保留当前平局规则：`max(pairs, key=lambda p: (pairs[p], p))`，即频次相同时选择按 bytes tuple 字典序较大的 pair。堆内过期项不得影响此规则。若某轮没有可合并 pair，则提前结束。special token 仍在预分词前切分并作为独立词表项，不跨 special-token 边界统计或合并。

该方法比每轮全量重算更复杂，但直接消除已知的全量扫描/重建瓶颈，并能以官方参考 merges/vocab 验证语义等价。更小的局部改动仍会每轮遍历全体片段，预计不一定达到速度门槛；本阶段不采用外部原生库或近似训练算法。

## 工作区边界

常规优化在嵌套仓库 `assignment1-basics` 的当前 `main` 分支上进行。只计划修改用户当前的 `cs336_basics/bpe.py`；已有 `tests/adapters.py` 修改及其它未提交/未跟踪内容必须保留。回归测试优先放在作业仓库之外，官方提供的测试与夹具不修改。特殊训练实验分支暂不创建；待其规则设计完成后再从常规基线分支独立开展。

## 验收

1. 小型回归测试验证相同预分词片段加权、重复/重叠 pair 的非重叠合并、平局选择、零候选终止、UTF-8 字节及 special-token 边界。
2. 官方 `tests/test_train_bpe.py` 三项全部通过：速度低于 1.5 秒；merges/vocab 与参考一致；special-token snapshot 一致。
3. 使用官方测试原样计时，不以工具测试或其它语料的速度替代。若环境噪声导致速度结果临界，记录实测，不声称通过。
4. 不运行或改写特殊训练版本，不覆盖、暂存或提交用户现有作业文件；是否提交代码由用户另行决定。
